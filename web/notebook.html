#2

報帳表格與 IAM 入門

2026-07-06

先做這件事

  • 提交表單前要完成 ≥5 個技能徽章
  • 其中 1 個必修：「Create your first Gemini Enterprise App」
  • 徽章要「完成」不是「開始」，早交表單不會提早拿到 voucher

表單欄位重點

  • 姓名 ＋ 註冊用（公司）email
  • 個人 email——要選真的收得到信的
  • Cohort ID：ASO3
  • 認證選 Associate Cloud Engineer，別選錯 PCA/PDE

Google Skills 個人檔案

  • 設定 → 公開可見度改成 Public
  • 要按儲存，不然連結不會生成
  • 把公開連結貼進表單

IAM 一句話

  • 誰（使用者/群組）＋能做什麼（角色）＋在哪個資源上
  • Predefined（Google 做好的）→ 優先試這個
  • Custom → 自己組合權限包
  • Basic（Owner/Editor/Viewer）→ 範圍最粗，最後手段

資源階層

  • Organization → Folder → Project → Resource
  • 上層授權會往下流：150 個專案要同權限，在 org 層設一次就好
  • Project ID 建立後鎖死；名稱之後還能改

Compute Engine 選型

  • 依負載選機型：compute／memory／network optimized
  • 頻寬跟 vCPU 成正比，上限 32 Gbps，要更快開 Tier 1 networking（100 Gbps，加錢）
  • VM 最少 1 個 internal IP
全域/區域/可用區小抄

Global：VPC、部分 Load Balancer。Regional：GCS bucket、subnet、GKE cluster（最多到這）、MIG。Zonal：VM 實例本身、Persistent Disk（多數情況）、Cloud SQL（預設）。VM 永遠是 zonal，這是最常考的陷阱。

#3

儲存的地圖：GCS 與 Cloud SQL

2026-07-13

儲存等級

  • Standard→Nearline→Coldline→Archive，越少用越便宜
  • Lifecycle Policy：自動依條件搬移／刪除
  • Autoclass：依實際存取自動換等級（少見）

加密金鑰三兄弟

  • GMEK：Google 管，預設，不用管
  • CMEK：你的金鑰，放在 Google
  • CSEK：你的金鑰，你自己保管（弄丟＝資料沒了）

鎖起來別亂動

  • Retention Policy：bucket 層級鎖定期限，鎖了不能刪
  • Object Hold：物件層級版本
  • 新規則：版本控管可以跟保留政策一起用了（舊教材可能寫錯）
  • Uniform bucket-level access：只用 IAM，關掉 ACL

Cloud SQL 高可用

  • 預設是單一可用區（zonal）
  • HA 勾選＝自動跨區容錯
  • Read Replica＝容錯要手動切換，別搞混！
  • 刪除/停止 instance 不會自動備份，只留 4 天
搬家小抄

外部資料要搬進 GCS？90–95% 情況都用 Storage Transfer Service。異質資料庫（例如 Oracle→Cloud SQL）搬家用 DMS。

#4

GKE 大冒險 与 運算選型

2026-07-20

Autopilot vs Standard

  • Autopilot：全自動、永遠是 regional、貴一點
  • Standard：你自己管、可 zonal 也可 regional、便宜
  • 小 pilot 專案不需要 HA → 選 zonal Standard

私有集群連外

  • 沒有外部 IP 的節點 = Private Cluster
  • 連 Google 服務 → Private Google Access
  • 連外部網路 → Cloud NAT
  • Workload Identity：K8s SA 直接借用 GCP SA，不用金鑰檔

三選一：怎麼跑 Web App

  • Cloud Functions：純事件驅動，不是拿來跑網站的
  • App Engine：Standard 可縮到零／Flexible 至少開一台
  • Cloud Run：需 stateless；兩者都行時優先選它

Terraform 口訣

  • 四檔案：cloudbuild config／backend.tf／tfstate／main.tf
  • 四指令：init → plan → apply → destroy
合規陷阱

Google 拿到 PCI-DSS / GDPR / HIPAA 認證，不代表你蓋在上面的系統也自動合規——這是共同責任。考題常考「怎麼強制資料留在特定地區」→ 答案是 Organization Policy，不是問你合不合規。

#5

BigQuery 與資料倉儲家族

2026-07-27

三個很像的名字

  • Filestore：NFS 檔案共享，不是資料庫
  • Firestore：NoSQL 文件資料庫
  • Firebase：App 開發平台，不是資料庫

BigQuery 省錢三招

  • 查詢快取：一樣的查詢 24 小時內免費重跑
  • Table Expiration：資料到期自動刪，不用手動追
  • Partitioning + Clustering：只掃需要的那一小塊資料

Cloud Spanner 特異功能

  • 唯一能水平擴展的關聯式資料庫（加節點就變快）
  • 代價：DB 邏輯（trigger／預存程序）要搬到應用層
  • 代價：綁定 GCP，換雲商不容易

Bigtable 是誰的菜

  • Key-Value、寬欄、時序資料首選
  • 要「讀取密集＋超低延遲」的分析 → 也可以用它取代 BigQuery
指令口訣

所有 gcloud 指令都是 gcloud [群組] [子群組] [動作]，例如 gcloud compute snapshots list。快照沒有 get 這個動作，只有 list／describe／delete。

#6

HA、DR 與畢業考前準備

2026-08-03（最終堂）

HA＝自動應變

  • Compute Engine → Regional MIG + LB
  • GKE → Regional Cluster + LB
  • App Engine／Spanner／GCS → 本來就高可用，免設定
  • Cloud SQL → 勾 Multi-zone

DR＝需要人做決定

  • Cold：備份還原，慢但簡單
  • Warm：跨區 Read Replica，快一點但手動切換
  • Hot：Cloud SQL 原生沒有，要改用 Cloud Spanner
  • DR 永遠不是全自動——跟 HA 最大不同

身分別搞混

  • Service Account：機器對機器
  • Cloud Identity：管理「人」的帳號（例如從 AD 匯入）
  • PII 資料 → 細粒度權限優於「有到期時間的分享連結」

報名考試小抄

  • 約 50 題 / 2 小時
  • 考場版：帶身份證件即可
  • 居家版：個人筆電＋鏡頭麥克風、房間要給監考官看一圈、考試中不能帶紙筆水食
最容易考錯

「哪個服務最簡單」跟「哪個服務最好」常常答案不同！例如靜態網站「最簡單」是 GCS + Load Balancer，但「最佳」通常才是 App Engine。看清楚題目問的是哪一個。
