01出題邏輯：情境題 > 死背題

STEP 1

先抓限制條件關鍵字：不可預測負載、highly available、特定日期、機器對機器⋯

STEP 2

用關鍵字直接消去不可能的選項（技術不符、範圍不對、非最佳實務）

STEP 3

剩下選項比「最省事／Google 推薦」的那個——同樣正確時通常只有一個更優解

02逐堂重點回顧

  • Resource Hierarchy：Organization → Folder → Project → Resource，權限由上往下繼承
  • IAM 角色優先序：Predefined → Custom → Basic（最後手段）
  • BigQuery：檢視要 dataViewer，查詢要另外的 jobUser
  • 常考陷阱：VM 永遠 zonal，GKE 最多 regional，GCS 最多 multi-region（非 global）
  • VM 最少要 1 個 internal IP；Spot VM 省 90% 但可被收回；MIG 分 stateful / stateless
  • 儲存等級遞減：Standard→Nearline→Coldline→Archive
  • 加密三層：GMEK(預設)／CMEK(自帶金鑰存Google)／CSEK(自己保管)
  • Retention Policy（bucket）vs Object Hold（物件）；Versioning 現可與 Retention 併用（新規則）
  • Cloud SQL：HA=自動容錯；Read Replica=手動容錯；刪除 instance 不自動備份，僅留 4 天
  • 外部搬資料進 GCS：首選 Storage Transfer Service
  • NoSQL 走 BASE（非 ACID），schema 彈性、邏輯下放應用層
  • Google 合規認證 ≠ 客戶系統自動合規（共同責任）；強制地區用 Organization Policy
  • Autopilot(全託管/永遠regional/貴) vs Standard(可zonal或regional/便宜)
  • Private Cluster：連 Google 服務用 Private Google Access，連外部用 Cloud NAT
  • Workload Identity：K8s SA 代用 GCP SA，免金鑰檔
  • Terraform 指令：init → plan → apply → destroy
  • CI/CD：Source Repo → Cloud Build → Artifact Registry → 弱點掃描 → Binary Authorization（守門）→ 部署
  • Filestore(NFS) vs Firestore(NoSQL文件) vs Firebase(App平台) —— 三個名字像但完全不同
  • Spanner：唯一水平擴展的關聯式資料庫，但邏輯要搬應用層 + vendor lock-in
  • BigQuery：欄式資料庫，成本看掃描量；查詢快取 24 小時；Partitioning + Clustering 優化速度成本
  • Bigtable：key-value/寬欄/時序資料首選，讀取密集低延遲分析也適用
  • 快照指令固定 gcloud [group] [subgroup] [verb]，沒有 get
  • Cloud Function Gen1(隱藏Pub/Sub) vs Gen2(顯式 Eventarc，較好除錯)
  • PII 資料：細粒度權限優於 signed URL
  • 靜態網站「最簡單」＝GCS+全域LB(backend bucket)；跟「最佳」(App Engine)不同答案
  • HA：Compute Engine/GKE 靠 Regional+LB；App Engine/Spanner/GCS 本來就高可用；Cloud SQL 勾 Multi-zone
  • DR：Cold(備份)／Warm(跨區Read Replica，手動)／Hot(Cloud SQL不支援，需換Spanner)
  • 金鑰選擇：公開資料→API Key；代表使用者→OAuth2.0；代表SA且資源在GCP內→環境憑證；代表SA且資源在GCP外→Service Account Key
  • 考試：約 50題／2小時，居家版需個人筆電+鏡頭麥克風+房間檢查

03必考觀念地圖

IAM

Predefined > Custom > Basic；Service Account 用於機器對機器溝通

資源範圍

VM / Cloud SQL = zonal；GKE 最多 regional；VPC = global

運算選型

事件驅動→Functions；容器＋免管理→Cloud Run；需自訂OS→Compute Engine；混合雲→Anthos

儲存選型

結構化+跨區→Spanner；分析+大量資料→BigQuery；NoSQL文件→Firestore；key-value/時序→Bigtable；檔案共享→Filestore

HA vs DR

HA＝自動容錯（zone層級）；DR＝人工決策（region層級，Cold/Warm/Hot）

安全

Uniform bucket-level access；PII用細粒度權限非signed URL；GCP合規≠客戶系統自動合規

Terraform

init → plan → apply → destroy

gcloud 語法

gcloud [group] [subgroup] [verb]，如 gcloud compute snapshots list

04易混淆點（點卡片看解答）

容易搞混

Filestore / Firestore / Firebase 是同一種東西？

正確觀念

三個完全不同：Filestore=NFS檔案服務、Firestore=NoSQL文件資料庫、Firebase=App開發平台（可搭配Firestore）。

點我翻面
容易搞混

App Engine 跟 Cloud Run 技術上都能用，選哪個？

正確觀念

兩者都可行時，Google 建議優先選 Cloud Run——考試遇到「兩者皆可」的題目，Cloud Run 是更優解。

點我翻面
容易搞混

HA 跟 DR 是同一回事嗎？

正確觀念

不是。HA 是自動化處理 zone 層級失效；DR 是處理整個 region 失效，且一定需要人工介入做決策。

點我翻面
容易搞混

Object Versioning 跟 Retention Policy 能一起用嗎？

正確觀念

規則已變更：現在可以併用了。舊教材可能寫「互斥」，考試以新規則為準。

點我翻面
容易搞混

gsutil 現在還是標準指令嗎？

正確觀念

gsutil 已淘汰，改用 gcloud storage；但考題可能仍出現舊語法，兩者都要認得。

點我翻面
容易搞混

Cloud SQL 的 Read Replica 容錯是自動的嗎？

正確觀念

不是，Read Replica 容錯是手動切換。自動容錯要靠 HA（Multi-zone）核取方塊。

05讀書策略建議

  • →依「資源歸屬服務」分類記憶（哪個服務原生 zonal/regional/global），比背個別定義更有效率——很多考題就是繞著這個範圍設陷阱。
  • →每個服務至少記住：適用情境 ＋ 不適用情境，因為出題常用排除法設計干擾選項。
  • →考前用課程提供的兩份 Google Form 練習題（各 ~30 題，目標正確率 80%+）與自建練習 App 做最後驗收。
  • →建議讀書順序：IAM/資源階層 → 運算(Compute/GKE/Serverless) → 資料儲存 → 網路 → 安全/合規 → HA/DR → IaC(Terraform)。
